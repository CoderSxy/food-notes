# 美食记录与 AI 推荐平台 — 设计说明

**日期：** 2026-10-28  
**状态：** 已确认  
**技术路线：** Next.js（App Router）+ Supabase + Vercel

## 1. 目标

做一个**多人注册的公开 Web 平台**：用户可用手机号验证码登录，登记美食信息（含定位、菜系、多标签、五分评分），并基于当前位置让 AI 推荐美食。要求**免运维部署、浏览器可访问**；AI 使用自建 OpenAI 兼容接口。

### 第一版范围（MVP）

- 手机号验证码登录（**测试模式**：验证码写入服务端日志 / 开发可见处，短信通道以后再接）
- 登记美食：定位、菜系（多选）、标签（多个）、评分（1–5 分）、名称与备注
- 列表 / 详情
- 「附近 AI 推荐」：当前位置 + 附近已有记录 → 调用自建模型

### 明确不做（第一版）

- 真实短信发送（阿里云 / 腾讯云等留接口，不接生产通道）
- 支付、社交关注、复杂地图编辑器
- 原生 App

## 2. 架构

```
浏览器 (Next.js)
  ├─ 页面：登录 / 首页列表 / 登记 / 详情 / AI 推荐
  └─ 调用 Route Handlers
        ├─ 验证码发送 & 校验（测试模式打日志）
        ├─ 美食 CRUD（经 Supabase，受登录态与 RLS 约束）
        └─ AI 推荐（服务端持有 API Key，查询附近 foods 后请求模型）
Supabase Postgres
  └─ users / otp_codes / cuisines / tags / foods / 关联表
Vercel
  └─ 托管 Next.js；环境变量存放密钥
```

- **前端 / BFF：** Next.js App Router + Route Handlers  
- **数据与账号：** Supabase Postgres；会话可用 httpOnly cookie / JWT（实现阶段选定一种，与 Supabase 客户端一致）  
- **部署：** Vercel 生产环境，公开 URL  
- **AI：** 仅服务端请求 `AI_BASE_URL`，模型名与 Key 来自环境变量，**不进仓库**

## 3. 数据模型

### 3.1 `users`

| 字段 | 说明 |
|------|------|
| id | UUID，主键 |
| phone | 手机号，唯一 |
| nickname | 昵称，可空，默认可由手机号派生 |
| created_at | 创建时间 |

### 3.2 `otp_codes`

| 字段 | 说明 |
|------|------|
| id | UUID |
| phone | 手机号 |
| code | 验证码 |
| expires_at | 过期时间 |
| consumed_at | 使用时间，可空 |
| channel | 预留：`test` / 日后 `aliyun` / `tencent` |
| created_at | 创建时间 |

测试模式：生成验证码后写入服务端日志（或仅开发环境可读的调试接口），`channel = test`。

### 3.3 `cuisines`（菜系字典）

| 字段 | 说明 |
|------|------|
| id | UUID |
| name | 如川菜、粤菜、日料 |
| slug | 稳定英文或拼音键，可选 |

种子数据在迁移或 seed 脚本中写入常用菜系，可后台扩展。

### 3.4 `tags`（自由标签）

| 字段 | 说明 |
|------|------|
| id | UUID |
| name | 标签名，唯一（规范化大小写 / 空白后） |
| created_at | 创建时间 |

一条美食可打**多个**标签；登记时可选择已有或创建新标签。

### 3.5 `foods`

| 字段 | 说明 |
|------|------|
| id | UUID |
| user_id | 创建者，关联 users |
| name | 店名或菜名 |
| note | 备注，可空 |
| rating | **1–5 整数**，五分制 |
| lat / lng | 经纬度 |
| address_text | 可选地址文案 |
| created_at / updated_at | 时间戳 |

### 3.6 关联表

- `food_cuisines`：`food_id` + `cuisine_id`（多对多）  
- `food_tags`：`food_id` + `tag_id`（多对多）

### 3.7 权限（RLS 原则）

- 登录用户可读公开列表（第一版：已登录可读全部美食；未登录不可写、不可调 AI）  
- 仅创建者可更新 / 删除自己的 `foods`  
- `otp_codes` 仅服务端角色可读写  

## 4. 核心页面与流程

1. **登录**  
   输入手机号 → 请求发送验证码 →（测试模式从日志取码）→ 提交验证码 → 建立会话 → 进入首页。

2. **首页**  
   最新 / 附近美食列表；入口「记一笔」「AI 推荐」；展示评分、菜系、标签摘要。

3. **登记**  
   请求浏览器定位（可拒绝后改为手动填大致位置）；填写名称、备注；多选菜系；多标签；**五分评分**；保存。

4. **详情**  
   单条美食完整信息。

5. **AI 推荐**  
   取当前位置 → 服务端按距离取附近 `foods`（含菜系、标签、评分）→ 组装提示词 → 调用自建模型 → 展示推荐条目与理由。  
   附近无数据时：说明样本不足，引导去登记，**不编造不存在的店名**。

## 5. AI 集成

- **Base URL：** 环境变量 `AI_BASE_URL`（约定为 OpenAI 兼容 `/v1`）  
- **Model：** 环境变量 `AI_MODEL`（如 `deepseek-v4.1-flash`）  
- **Key：** 环境变量 `AI_API_KEY`，仅服务端  
- 推荐接口需登录；超时与 4xx/5xx 返回友好错误，不影响列表与登记  
- 提示词输入：用户坐标、附近记录摘要（名称、距离、菜系、标签、评分、备注截断）、输出格式约定（JSON 或结构化 Markdown，实现计划中定一种并校验）

## 6. 出错处理

| 场景 | 行为 |
|------|------|
| 定位被拒 | 允许手动输入 / 点选大致位置后再登记或推荐 |
| 验证码错误或过期 | 提示并支持重发；测试模式码在服务端日志可见 |
| AI 超时或 Key 失效 | 友好报错；列表与登记可用 |
| Supabase / 网络失败 | 可重试；尽量保留未提交表单内容 |

## 7. 部署与仓库

- **托管：** Vercel 连接仓库，自动部署  
- **环境变量（示例名）：** `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`、`SUPABASE_SERVICE_ROLE_KEY`（仅服务端）、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、会话密钥等  
- **仓库：** 公开 Git 仓库；README 说明本地启动、Supabase 迁移、Vercel 与环境变量；**.env 不入库**，提供 `.env.example`（无真实密钥）  
- **密钥：** 用户提供的 API Key 只写入部署环境变量，不出现在提交历史中  

## 8. 组件边界（便于实现与测试）

| 单元 | 职责 | 依赖 |
|------|------|------|
| OTP 服务 | 生成、存储、校验验证码；测试通道打日志 | otp_codes 表 |
| 会话 | 登录后签发与校验 | users |
| Foods API | CRUD + 附近查询 | foods、关联表、RLS |
| 标签 / 菜系 | 列表、创建标签、绑定 | cuisines、tags |
| Recommend API | 查附近 + 调 AI + 解析结果 | Foods 查询、AI 客户端 |
| AI 客户端 | OpenAI 兼容 chat completions 封装 | 环境变量 |

## 9. 测试要点（MVP）

- OTP：正确码登录、错误码、过期码、测试日志中可见码  
- 登记：无定位时的降级；评分仅允许 1–5；多菜系多标签保存与回读  
- 附近查询：距离排序合理  
- AI：有样本时返回可解析结果；无样本时不编造店名；Key 缺失时明确错误  
- 权限：未登录不能写美食 / 调推荐；不能改他人记录  

## 10. 成功标准

- 公开 URL 可打开，新用户能用手机号（测试验证码）完成注册登录  
- 能完成一条带定位、菜系、多标签、五分评分的登记并在列表看到  
- 登录用户能基于位置拿到 AI 推荐（有数据时）或明确的「样本不足」提示（无数据时）  
- 仓库公开、文档可跟着 README 跑通本地与 Vercel 部署（密钥自备）  

## 11. 已确认的产品决策摘要

- 受众：公开平台，多人注册  
- 登录：手机号验证码；短信先测试模式  
- AI：自建平台 OpenAI 兼容 API；模型与 Base URL 可配置  
- 栈：Next.js + Supabase + Vercel  
- 标签可多个；评分五分制整数
