# R2 Optional Photos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Owner preference:** Prefer **Cloud Agent** for implementation; if unavailable, fall back to **Claude Code**. Spec: `docs/superpowers/specs/2026-11-01-r2-photos-design.md`. Never commit secrets or real R2 keys.

**Goal:** Let users optionally attach up to 3 photos per place/item entry: browser-compress to ~1MB, presigned PUT to Cloudflare R2, show cover on list/map and gallery on detail; owners can add/remove after save.

**Architecture:** New `entry_photos` table. Server issues S3-compatible presigned PUTs (`@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner`) and never handles file bytes. Client compresses (Canvas → WebP/JPEG), PUTs to R2, then `confirm` inserts the row. List/map attach `cover_photo_url` (sort=0); detail attaches `photos[]`. Missing R2 env → text entries still work; picker shows 「图片存储未配置」.

**Tech Stack:** Next.js 15 App Router, React 19, Supabase (service role), Cloudflare R2 (S3 API), Zod, Vitest + Testing Library (jsdom), warm 食记 CSS, Chinese UI copy.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-11-01-r2-photos-design.md`
- Prefer Cloud Agent; fallback Claude Code
- Max **3** photos per entry; optional; album + `capture` camera + paste
- Compress: long edge ~2048, target ~1MB, hard cap ~1.2MB; prefer WebP else JPEG
- Object key: `entries/{userId}/{entryId}/{photoId}.webp` (or `.jpg`)
- Auth: `requireUser` + Bearer session; only entry owner can presign/confirm/delete
- Login-visible: any signed-in user can see photos on entries they can already see
- Env (server only): `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `R2_PUBLIC_BASE_URL`, optional `R2_ENDPOINT`
- Never commit secrets / `.env.local` / real keys
- When R2 unset: create/list/detail still work without photos; upload APIs return clear Chinese 503/400
- Vitest include is `tests/**/*.test.ts` only — component tests must use `.test.ts` (not `.tsx`)
- `npm test` and `npm run build` must pass
- Migration number: **006** (`005_dashboard_indexes.sql` already exists)
- Warm 食记 styling; Chinese error/UI copy

```sql
-- supabase/migrations/006_entry_photos.sql
create table if not exists public.entry_photos (
  id uuid primary key default gen_random_uuid(),
  entry_id uuid not null references public.entries(id) on delete cascade,
  user_id uuid not null references public.users(id) on delete cascade,
  r2_key text not null,
  public_url text not null,
  sort int not null check (sort >= 0 and sort <= 2),
  width int,
  height int,
  bytes int,
  content_type text not null,
  created_at timestamptz not null default now(),
  unique (entry_id, sort),
  unique (r2_key)
);

create index if not exists entry_photos_entry_id_sort_idx
  on public.entry_photos (entry_id, sort);

comment on table public.entry_photos is 'Optional entry photos stored in Cloudflare R2; max 3 per entry enforced in app.';
```

### Task 4: Photo API routes

**Files:**
- Create: `app/api/photos/presign/route.ts`
- Create: `app/api/photos/confirm/route.ts`
- Create: `app/api/photos/[id]/route.ts`
- Reuse: `requireUser`, `privateJson`, `apiError`, `HttpError`, `getEntry`

**Behavior:**

**POST `/api/photos/presign`**
1. `requireUser`
2. If `!isR2Configured()` → 503 「图片存储未配置」
3. Parse body with `photoPresignSchema`
4. `getEntry(entryId)`; 404 if missing; 403 if `entry.user_id !== user.userId`
5. If `countPhotos >= 3` → 400 「最多 3 张照片」
6. `photoId = crypto.randomUUID()`; `r2Key = buildObjectKey(...)`; `publicUrl = publicUrlForKey(r2Key)`
7. `uploadUrl = await presignPutObject(r2Key, contentType)`
8. Return `{ uploadUrl, r2Key, publicUrl, photoId, headers: { 'Content-Type': contentType } }`

**POST `/api/photos/confirm`**
1. Same auth + R2 check + ownership
2. `assertKeyOwned`; re-check count < 3
3. `insertPhoto`; return `{ photo }`

**DELETE `/api/photos/[id]`**
1. Auth; load row by id; 404/403
2. Delete DB row; best-effort `deleteR2Object(r2_key)`
3. Return `{ ok: true }`

Export `dynamic = 'force-dynamic'` on each route.
